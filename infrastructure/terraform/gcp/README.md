# Déploiement de démonstration sur une VM privée

Le projet Google doit disposer de facturation, de Compute Engine, d’IAP et des autorisations SSH. Dimensionner le disque système pour les quatre images, archives, copies restaurées et checkpoints. Le volume OSD est dédié à Ceph. Un seul OSD ne fournit aucune redondance.

1. Dans infrastructure/terraform/gcp, exécuter `terraform init`, puis `terraform plan -var project_id=PROJET -var boot_disk_gb=TAILLE -out=deployment.tfplan`. Appliquer le plan examiné avec `terraform apply deployment.tfplan`. L’output donne la commande SSH IAP.
2. Copier le checkout de la PR sur la VM, attendre la fin du script de démarrage puis lancer depuis la racine du dépôt `sudo bash infrastructure/terraform/gcp/bootstrap-ceph.sh`. Le script utilise le disque google-ceph-osd et crée le bucket RGW, les identifiants privés et les services PostgreSQL, REST et Trino.
3. Planifier une fenêtre de coupure et arrêter proprement les écritures puis Connect, Kafka et les deux bases. Depuis Ubuntu-Test, lancer `sudo python3 scripts/migrate_cdc_stack.py backup /CHEMIN/ARCHIVE` sur un volume suffisamment grand. L’archive contient des données et secrets. La transporter via SSH IAP en préservant les propriétaires numériques et les permissions (tar en tant que root aux deux extrémités). Restaurer sur la VM avec `sudo python3 scripts/migrate_cdc_stack.py restore /CHEMIN/ARCHIVE`. La restauration exige des noms de conteneurs libres. Elle reproduit images, montages et alias réseau, publie les ports sur localhost et démarre Connect en dernier. Comparer les comptes SQL des sources et vérifier les tâches des connecteurs.
4. Dans un shell root sur la VM, depuis le dépôt, exécuter `set -a; source /etc/fema-lakehouse.env; set +a`, puis `FEMA_CHECKPOINT_NAME=ceph_bronze_v1 KAFKA_STARTING_OFFSETS=earliest bash scripts/run_demo_pipeline.sh --once`. Le catalogue REST utilise S3FileIO sur Ceph. Les checkpoints restent sur le disque système. Comparer la rétention Kafka à la profondeur requise pour reconstruire le Bronze. Une archive Kafka tronquée ne remplace pas l’historique Bronze.
5. Vérifier `docker compose -f infrastructure/docker/compose.lakehouse.yml exec trino trino --execute 'SELECT * FROM iceberg.gold.entity_counts ORDER BY entity, source_system'`. Récupérer tout le dossier du projet Power BI généré pour l’ouvrir sous Windows.
6. La VM, le NAT et les disques peuvent être facturés. Le disque Ceph est protégé par prevent_destroy. Conserver aussi les métadonnées PostgreSQL, la configuration et les clés Ceph sur le disque système avant tout démontage définitif.
